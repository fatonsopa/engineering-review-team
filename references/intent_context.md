# Project intent and guidance

## Discover relevant guidance

Start with the task, supplied links, repository instructions and known project document locations. Use targeted search for unfamiliar scope, changed indexes, newly linked documents, conflicting guidance or missing essential requirements. Reuse known locations and unchanged context; do not rescan the whole project for every task. Stay within authorized roots and state material access limits.

Documents are optional and may combine several purposes. Route by content rather than filename. Read relevant sections rather than every document. A missing optional document does not itself prove a code defect or stop supported technical review.

## Review scope and criteria

The lead gives reviewers the requested behavior, source subset, applicable project rules and package defaults, relevant document sections, constraints and known gaps in a normal assignment. Explain source authority and version when material. No separate criteria registry, IDs or per-criterion record is required.

Apply actual user-authorized supplements, replacements and waivers. Identify the affected rules and scope, including expiry where relevant. A replacement displaces the mapped default; a waiver records an exception and residual consequence rather than pretending conformity. A conflicting supplement needs resolution. Inferred conventions, proposals, obsolete decisions and measured results do not silently become obligations. Ask about material ambiguity while continuing supported work.

## Team document ownership and routing

Use the [project documents and roles table](../README.md#project-documents-and-roles) to select relevant sections and recipients. The lead routes only content needed for the assigned review.

## Compare and report

Compare implementation with effective intent and legitimate alternatives. Describe supported contradictions, partial fulfillment, unknowns and unreviewed areas in ordinary prose. Do not turn an unavailable contract into an invented guarantee. A question or partial review may still contain useful findings.

If source or governing guidance changes during review, inspect the affected change and qualify earlier conclusions. Preserve relevant original evidence without creating a versioned review-state system. Use the shared [findings and handoff guidance](review_standard.md).
