## Primary sources and decisions

All sources below were opened during this research on 2026-11-04. Versions describe the consulted source, not an assumed target environment. No source grants permission to run its commands or adopts its examples as project budgets.

| Source | Version/context inspected | Decision supported |
| --- | --- | --- |
| [Go diagnostics](https://go.dev/doc/diagnostics) | Living official documentation; profiling, tracing and instrumentation interference | Select evidence for the question. CPU samples concern active CPU time, not all waiting; allocation, heap, blocking and contention evidence answer different questions. Instrumentation can affect results. Runtime-specific interpretation must match the target. |
| [Profiling Go Programs](https://go.dev/blog/pprof) | Historical Go article, published 2011 and updated 2013 | Bind comparisons to compiler/runtime, machine, input and method. Use this article's diagnostic reasoning, not its old commands, performance figures or historical versions as current defaults. |
| [Google monitoring distributed systems](https://sre.google/sre-book/monitoring-distributed-systems/) | Site Reliability Engineering book, 2016 | Examine latency distributions, traffic, errors and saturation according to the question. Separate successful and failed work; favorable averages do not describe tail experience. This does not mandate a monitoring stack or universal metrics. |
| [Google handling overload](https://sre.google/sre-book/handling-overload/) | Site Reliability Engineering book, 2016 | Request counts alone can misrepresent resource demand when request cost varies. Capacity analysis needs the actual workload and constrained resources; overload controls and graceful degradation must preserve the project's required behavior. Google's deployment scale is not a target requirement. |
| [Grafana k6 open and closed models](https://grafana.com/docs/k6/latest/using-k6/scenarios/concepts/open-vs-closed/) | Living documentation displayed v2.3.x | Interpret the offered-load model. A closed model reduces arrival rate when completions slow and cannot by itself demonstrate behavior under an independent fixed arrival rate. Both models can be appropriate; k6 is not required. |
| [Google web.dev lab and field differences](https://web.dev/articles/lab-and-field-data-differences) | Living article; lab versus field populations and conditions | Preserve device/network/population and journey scope. Controlled lab results and real-user observations answer related questions but are not interchangeable guarantees. Neither source requires a universal score or metric threshold. |
| [RFC 9111: HTTP Caching](https://www.rfc-editor.org/rfc/rfc9111.html) | IETF Standards Track, June 2022, sections 3–5 | Caching has storage, freshness, validation, cache-key and authenticated-response semantics. Proposed reuse must preserve those applicable guarantees; absent caching is not itself a defect. |
| [OpenAI Codex subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents) | Living official documentation; approvals/sandbox and custom-agent sections | Codex custom agents inherit parent permissions. Read-only instructions do not create a separate sandbox. Proposed role identity needs actual configuration and host validation before support is claimed. |
| [Anthropic skill authoring practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices) | Living official documentation; concise instructions and progressive disclosure | Keep shared ownership, selective references and clear procedures. The 500-line recommendation concerns root `SKILL.md`; it does not impose a standard-file size limit or prescribe our control/file/role count. |

The last two sources refresh the prior DevOps research because their claims determine new-role authoring limits. The role/policy split, 12-control catalogue and reviewer boundaries are package design decisions supported by the user's requested organization, not vendor-mandated architecture. No token reduction or behavioral improvement has been measured.
